# 27: Page keys toggle their page

**What to build:** The key that opens a page also closes it when it is pressed again: press M and the Automap opens and the game pauses; press M again and the Automap closes and the game goes on. The same holds for I (the inventory) and for the stat page, which gets Tab as a second key beside C (Tab and C both toggle it). A page key toggles only its own page. Esc keeps closing the open page and keeps declining the question whether to sail home. Each page also tells the player so: the close hint at the foot of a page names the page's own key or keys as well as Esc ("M OR ESC TO CLOSE" on the Automap, "I OR ESC TO CLOSE" on the inventory, and both C and Tab on the stat page), where it now says only "ESC TO CLOSE".

**Blocked by:** None (can start immediately)

**Status:** resolved

**Spec stories:** 64, 73, 87, 92, 93, 108

## Comments

Added at the player's request during playtesting ("m and i and tab should be toggle buttons"). Decided with the player: Tab is a second key for the stat page (C keeps working), a key of another page stays ignored while a page is open (it does not switch pages), and the pages' close hints name the page's own key as well ("yes add the toggle keys as well"). Spec story 108; the key list and the Testing Decisions of the spec were amended to match.

For the implementer: the hints are drawn in three places of the adapter (the Automap page draws its own centred line, the inventory and the stat page have a text row each in the overlay); `overlay.ts` cuts text that is too long for its window, so the length of the hint on the stat page is worth a test. The page keys are one key each today (`PAGE_KEYS`), and the stat page needs two: tickets 28 and 29 build on the same table, so keep it a table of keys for each page. This ticket does not add the Controls page (ticket 28).

**What was built (ticket 27).**
- Core: a new command `toggle-page` (`{ type: 'toggle-page', page }`), run by `togglePage` in `src/core/pages.ts`. It closes the page when that page is the one that is open, and otherwise opens it as `open-page` does. The events are the same `page-closed` and `page-opened` as before.
- Adapter: `PAGE_KEYS` in `src/adapter/controls.ts` is now a table of keys for each page (`name`, `label`, `capture`): C and Tab for the stat page, I for the inventory, M for the Automap. The binding in `player-input.ts`, the start-up key-clash check (`keysOfEverythingElse`), `pageKeyLabel` and the new `pageCloseHint` all read it. `PlayerInput` sends `toggle-page` when a key of a page is pressed again; Esc is unchanged.
- Hints: `pageCloseHint(page)` gives "C/TAB OR ESC TO CLOSE", "I OR ESC TO CLOSE" and "M OR ESC TO CLOSE". The overlay's two rows use it, and `automap-page.ts` has `AUTOMAP_HINT` (the text and the room of its window).
- README (controls table, "Pages and the pause", "To add a page", a new bullet on the hint, the tests) and `docs/playtest-checklist.md`, in the same commits as the code.

**Decisions.**
1. A new command, not "a repeated open closes". `open-page` on the open page is ignored and existing tests pin that, and a command named open should not close. So `open-page` is untouched and the rule of which of the two a key does stays in the core: the adapter does not read the view.
2. `togglePage` closes in every state in which `close-page` does (a restored save that also waits for a Stat Point or the answer included), and opens only as `open-page` does: the key of another page does nothing while a page is open, and nothing opens while a Stat Point waits or the question is open.
3. One toggle however many keys of a page go down: C and Tab together toggle once. A key that is held, repeated by the keyboard, or already down when the screen began is not a press.
4. A page key pressed with Ctrl or Cmd now asks nothing, as the other game keys already did (Ctrl+Tab, Cmd+Tab and Cmd+M belong to the browser or the system). One old behaviour changes with it: Ctrl+C used to open the stat page and no longer does (it is the copy shortcut). Alt and Shift are not filtered, as before.
5. Only Tab is held back from the browser (`capture: true`); C, I and M stay `false`, as before, so Ctrl+C and the like keep working. Phaser's capture is page-wide and is not undone when the scene ends, so Tab stays held back on the title once a game has begun, where it does nothing. Phaser holds back only an unmodified press, so Shift+Tab and Ctrl+Tab still reach the browser.
6. The wording "C/TAB OR ESC TO CLOSE" is 21 letters, 125 px, in the stat page's 136 px text room (22 letters); "C OR TAB OR ESC TO CLOSE" would be 143 px and overrun. The inventory's room is 274 px and the Automap's 276 px, worked out by hand in the test.
7. The implementer note above says `overlay.ts` cuts text that is too long. It does not: only gear and key names are fitted, and a text row is centred as it is given, so a hint wider than its room runs over the window. The fit test is the only guard.
8. Left as they are on purpose: "ESC TO STAY" (the question) and "ESC TO KEEP IT" (the title); the notice "PRESS I TO EQUIP" (it reads `pageKeyLabel`); `SNAPSHOT_VERSION` (the save is untouched); the random command generator of `tests/saved-game-walks.test.ts` (a new command in it would shift its seeded walks). No H key, Controls page or title line (tickets 28 and 29).

**Expectations that changed.** `tests/controls.test.ts`: the clash-table row of M says 'toggling the automap page' where it said 'opening the automap page', because `keysOfEverythingElse` now names the toggle (the clash is still refused and named). New rows in the exhaustive tables of `tests/departure.test.ts` and `tests/ending.test.ts`. The README controls table and text, and the checklist lines for C/Tab, M and I.

**Tests, and that each can fail** (every break below was made, seen red and reverted; the tree is clean after each):
- `tests/toggle-page.test.ts` (48, at the core's interface): a toggle that never closes (27 red); a toggle that closes whichever page is open (12 red, all of "another page's key"); a toggle that does not close while the question is open (3 red). The row in `tests/ending.test.ts` cannot be turned red by changing the source: the compiler already forces the phase guard of the `toggle-page` case.
- `tests/player-input.test.ts` and `tests/controls.test.ts`, on plain fake keys: no Ctrl/Cmd filter plus Esc closing one page too few plus default capture (6 red); page keys read by `justDown` only plus Tab not captured (7 red); one toggle per key plus the label of the last key (2 red); `open-page` sent instead (19 red). The rows "however long it stays down and the browser repeats it" pin Phaser's own rule for a held key, so no change of our source turns them red; the rows "already held before the screen began" are what guard the filter. The test of Tab with Ctrl, let go and pressed clean again, was shown red only through the command type.
