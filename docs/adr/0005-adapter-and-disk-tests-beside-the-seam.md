# Test the adapter's pure functions and the shipped files beside the seam, and never stand in for Phaser

Status: proposed in the code-review fix pass; the user may veto it, in which case the tests it lists are dropped.

Beside the three boundaries of ADR 0002, tests may (a) call the adapter's pure functions directly, the ones in modules that import Phaser only as a type, with values worked out by hand; (b) read the files the game ships from disk, where the code depends on a property of them (the size and frames of a sheet that the manifest relies on, the licence record against the files that ship, the credits against the record, the audio files against their manifest), and never to judge taste; and (c) never replace the Phaser module: code that needs a part of Phaser (its keys, the rectangles it draws with) reads it through a small interface that its own module declares, which a test fills with plain objects. What only a browser can show (Phaser drawing, the wiring of the scenes, the sound playing, how the art looks and how the sounds sound) is still not tested, so for that part ADR 0002's cost and ADR 0003's safety net (the compiler and Phaser's type definitions) stand, and each ticket that touches it carries a manual play check.

## The tests it covers

(a) The adapter's pure functions, in `tests/`: `area-banner`, `audio-line`, `automap-layout`, `automap-palette`, `camera`, `castle-final-art`, `departure-menu`, `departure-panel`, `ending-pages`, `fall`, `feedback`, `fixed-step`, `game-waiting`, `health-bar`, `mountain-cave-final-art`, `notice-lines`, `opening-card`, `pickup-rise-sprites`, `pixel-font`, `play-start`, `projectiles`, `row-stack`, `terrain-plan` and `the-title-logo`, each as `<name>.test.ts`. The tests of the shipped content that read the adapter's screen size, colours, text drawing, card layout or room for a name are of this kind too: `covered-corner`, `gear-names`, `shipped-areas`, `shipped-art`, `shipped-puzzles`, `the-castle`, `the-cave`, `the-credits`, `the-guardian` and `the-mountain`.

(b) The shipped files, read from disk: `final-art`, `castle-ground`, `mountain-cave-ground`, `castle-undead`, `castle-guardian-art`, `mountain-cave-monsters`, `gate-lever-art` and `vessel-art` read the pictures of `public/art/` (most through the helper `tests/pictures.ts`); `shipped-audio` reads `public/audio/`; `shipped-licences` reads the build, `index.html` and the licence record; `the-credits` reads the licence record through `tests/licence-record.ts`.

(c) Phaser's parts behind an interface: `player-input` fills the `Keyboard` and `KeyState` interfaces of `src/adapter/player-input.ts` with plain objects, and `controls` gives `checkAudioKeys` a plain function in place of Phaser's table of key codes; `pixel-font`, `notice-lines`, `departure-panel`, `the-credits` (through `tests/drawn-text.ts`), `opening-card` and `shipped-puzzles` record the rectangles of a text through the `Graphics` interface of `src/adapter/pixel-font.ts`. No test calls `vi.mock('phaser')`.

The three boundaries of ADR 0002 are tested as before: `saved-game`, `saved-game-sweeps`, `saved-game-walks`, `save-store` and `continue-after-checkpoint` (the saved game and its store), `audio-settings` (the settings) and `asset-manifest` (the missing-picture check).
