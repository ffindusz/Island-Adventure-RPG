# The Game core's interface is the only automated test seam

All gameplay rules live in a headless Game core, and tests use only its interface (commands and fixed time steps in; state view, events and snapshot out), because that keeps real-time combat deterministic and testable without a browser, whereas a second browser-level seam would be slower and flaky for it (agreed with the user on 2026-10-06). The cost is that nothing automatically checks Phaser rendering, key mapping, audio or art, so each ticket that touches the adapter carries a manual play check. The only exceptions are three thin boundaries, each tested through one public function with in-memory fakes: parsing a bad save (ticket 11), parsing settings (ticket 21) and the asset manifest's missing-item check (ticket 22).
